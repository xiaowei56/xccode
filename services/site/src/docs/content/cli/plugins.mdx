---
title: "CLI plugins"
description: "Load TUI plugins from your Xiaochuan config in the CLI, and add CLI-only plugins and their options in cli.json."
---

Plugins configured in `xiaochuan.json(c)` that expose a TUI component are loaded automatically by the CLI. To learn how
to build plugins, see [Building plugins](/build/plugins). You do not need to add the same package to `cli.json`. The CLI
gets the active plugin list from the connected Xiaochuan server, so this also works when the server is remote.

Use `cli.json` for CLI-only plugins. These plugins run locally in the terminal and remain active when the CLI connects
to a remote server:

```json title="cli.json"
{
  "plugins": [
    "xiaochuan.example",
    "xiaochuan.example@1.0.0",
    "@example/xiaochuan-tui",
    "@example/xiaochuan-tui@1.0.0",
    "./plugins/status",
    "../plugins/status",
    "/home/user/plugins/status",
    "file:///home/user/plugins/status"
  ]
}
```

Entries are processed in order. Prefix an ID or wildcard with `-` to disable matching plugins:

```json title="cli.json"
{
  "plugins": ["*", "-xiaochuan.notifications", "-team.*"]
}
```

Pass plugin options with the object form:

```json title="cli.json"
{
  "plugins": [
    {
      "package": "@example/xiaochuan-tui",
      "options": {
        "compact": true
      }
    }
  ]
}
```

Xiaochuan also discovers plugins under the global config directory and project `.xiaochuan` directories. Each plugin uses
the same layout as a published package, with server and TUI entrypoints kept together.

```text title="Plugin discovery paths"
<global-config>/plugins/status/index.ts
<global-config>/plugins/status/tui.ts
<project>/.xiaochuan/plugins/status/index.ts
<project>/.xiaochuan/plugins/status/tui.ts
```

Discovered plugins can import `@xiaochuan/plugin/tui` directly; Xiaochuan resolves the package at runtime. See
[Building TUI plugins](/build/plugins/cli) for examples.
